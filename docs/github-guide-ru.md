## Что находится в архиве

Папка `task2-research-methods` содержит исходники репозитория, включая английский README, карточку в Markdown, Dockerfile, зависимости, конфигурации, sample data, LICENSE, `.gitignore`, тесты и пример фактического запуска. Отдельный PDF предназначен для LMS. Промежуточные файлы сборки и большие логи в архив не включены.

Предположение о теме отмечено в README и карточке: **сравнение поиска целых чисел в Python list и set**. Сначала сверьте эту тему с Task 1. Если Task 1 другой, нужно согласованно заменить вопрос, гипотезы, переменные и измерительный код. Пример не выдаёт себя за неизвестную прежнюю работу.

## Проверить запуск

Распакуйте ZIP и откройте терминал в папке над `task2-research-methods`. Для проверенного окружения используйте CPython **3.12.14**. Если ваша команда называется `python3`, замените `python` на `python3` во всех командах.

```bash
cd task2-research-methods
python -m unittest discover -s tests -v
python src/benchmark.py --config config.json
```

Ожидается `OK` после 13 тестов, затем `COMPLETED` и `Hypothesis decision: not_evaluated`. Последнее правильно: sample проверяет инструмент, а не подтверждает гипотезу. Результаты будут в `results/smoke/`. Повторный запуск направьте в новую папку:

```bash
python src/benchmark.py --config config.json --output results/smoke-02
```

Сторонних Python-пакетов нет. В `requirements.txt` поэтому нет строк с библиотеками: фиксируется пустой набор зависимостей, а версия интерпретатора указана в `.python-version` и Dockerfile. Это полноценный работающий вариант без установки библиотек.

Для варианта с Docker выполните команды Docker из README. Docker отсутствовал при подготовке пакета, поэтому успешная сборка контейнера здесь не заявляется. На другом Python smoke допускается, но статистический вывод отключается; используйте зафиксированную версию для исследования.

## Обновить опубликованный репозиторий

Для дальнейших изменений используйте существующий клон и ветку `main`; не запускайте `git init` и не создавайте второй репозиторий. Перед коммитом выполните тесты и проверьте список staged-файлов: результаты запуска, секреты, архивы и кэши не должны попасть в публикацию.

```bash
git status --short --branch
git add -A
git status --short
git commit -m "Publish complete Research Methods Task 2 project"
git pull --ff-only origin main
git push origin main
```

Не используйте force push: исходная история репозитория должна оставаться доступной. Команды используют уже настроенное имя и email автора коммита; при запросе GitHub войдите обычным способом или через GitHub Desktop.

В GitHub Desktop откройте существующий клон, проверьте изменения и отправьте коммит в `main`. Не создавайте новый репозиторий и не загружайте ZIP вместо файлов проекта.

## Оформить вклад пары

Укажите в `CONTRIBUTIONS.md` только фактически выполненные действия. Там есть предложенное распределение, но оно не утверждает, что работа уже сделана. Не выдумывайте username участника, вклад или авторство коммитов.

После реальной проверки можно, например, уточнить методологию и добавить заметку о запуске на вашем компьютере. Используйте сообщения, описывающие конкретное изменение, например `Clarify primary metric and guardrails` или `Record local smoke validation`.

В карточке и README уже стоят указанные вами имена. В лицензии авторы также указаны. Название аккаунта `medetkb` не заменяет имена авторов в учебной работе.
